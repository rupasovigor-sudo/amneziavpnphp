# Запуск панели в прод

Панель — это **control-plane** (управление серверами/клиентами, DNS-failover, мониторинг, бэкапы). Сами VPN-серверы обслуживают клиентов независимо: **падение панели не роняет VPN**.

## 1. Требования к хосту панели
- Ubuntu 22.04/24.04 LTS или Debian 12, **виртуализация KVM** (не OpenVZ).
- Docker + Docker Compose v2.
- 1–2 vCPU, 2 GB RAM, диск от 20 GB.
- Доступ по SSH к VPN-серверам (панель ходит на них по кредам из БД).

> VPN-серверы: только **KVM** (нужны `/dev/net/tun`, netns, iptables для awg2 + WARP). IP берите из **разных ASN/диапазонов** — блокируют диапазонами. Swap на них деплой добавит сам.

## 2. Запуск
```bash
git clone <repo> && cd amneziavpnphp
cp .env.example .env
# отредактируй .env (см. п.3)
docker compose up -d
docker compose exec web composer install
# дождись healthy БД; миграции применяются автоматически (docker-entrypoint-initdb.d).
# для обновлений — применить миграции вручную:
set -a; source .env; set +a
for f in migrations/*.sql; do docker compose exec -T db mysql -u"$DB_USERNAME" -p"$DB_PASSWORD" "$DB_DATABASE" < "$f" || true; done
```
Панель поднимется на `http://<host>:8082`.

## 3. Обязательный `.env`
| Переменная | Назначение |
|---|---|
| `APP_ENCRYPTION_KEY` | **Ключ шифрования секретов в БД** (base64 32 байта). Уникальный на прод. **БЭКАПНИ ОТДЕЛЬНО** — без него не расшифровать ключи клиентов/токены. |
| `DB_*` | Креды БД (root/user/password/database). |
| `AMNEZIA_CSRF_ENABLED=1` | CSRF-защита. |
| `APP_ENV=production` | Прод-режим (не `local`). |

Токен Timeweb DNS — в UI: **Настройки → API** (для DNS-failover пула).

### Необязательные (есть разумные значения по умолчанию)
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CLIENT_ONLINE_WINDOW_SECONDS` | `600` | За сколько секунд с последнего handshake клиент считается онлайн. Один источник правды для страницы сервера и обоих поллингов. Увеличь, если статусы «дёргаются» у простаивающих клиентов. |
| `LIVE_STATUS_CACHE_SECONDS` | `20` | Кэш живого статуса пиров. Убирает по одному SSH на каждого члена пула на каждый опрос каждой вкладки. `0` — отключить кэш. |
| `AWG2_PIN_REF` | `master` | Ветка/тег/коммит amneziawg-go, из которого собирается awg2. **На проде задай конкретный коммит**, иначе любая пересборка затянет текущий master без ревью. |
| `AWG2_UPSTREAM_CACHE_SECONDS` | `3600` | Кэш запроса к GitHub при проверке версии awg2. |

## 4. Первый вход и настройка
1. Зайти под админом, **сменить пароль** на сильный.
2. **Настройки → API** — токен Timeweb (управление доменом пула).
3. **Бэкапы** — заполнить S3 (endpoint/region/bucket/key/secret) + **passphrase шифрования** (сохрани его в менеджер паролей!) + расписание → «Сохранить». Проверить «Создать бэкап сейчас».
4. Добавить серверы, собрать пул (общий домен), проверить failover.

## 5. Прод-хардненинг (обязательно)
- [ ] **HTTPS + reverse-proxy** (nginx/caddy/traefik + Let's Encrypt) перед `8082`. Панель отдаёт админ-логин, SSH-креды серверов, passphrase бэкапа — **голый HTTP недопустим**.
- [ ] **Фаервол**: доступ к панели только с доверенных IP/VPN. Порт `8082` не наружу без прокси.
- [ ] `APP_ENV=production`, CSRF включён.
- [ ] **Сильный пароль админа** (панель = root-SSH ко всем VPN-серверам, это crown jewel).
- [ ] `APP_ENCRYPTION_KEY` — уникальный, забэкаплен отдельно.
- [ ] **Бэкапы включены** (S3 + расписание) и проверены restore'ом.

## 6. Бэкап и восстановление (DR)
- **Что бэкапится:** вся БД (серверы + SSH-креды, идентичность пула, ключи клиентов, токены) + `.env`. Шифруется passphrase'ой, льётся в S3, ротация.
- **Расписание:** `bin/backup_cron.php` по cron (ежечасно, бэкапит по интервалу расписания).
- **In-place restore:** UI → Бэкапы → «Восстановить».
- **DR на новом хосте** (панель/хост умерли):
  ```bash
  # 1. новый хост: docker + репо + .env (креды БД)
  docker compose up -d
  # 2. достать APP_ENCRYPTION_KEY из бэкапа и вписать в .env:
  S3_ENDPOINT=... S3_REGION=... S3_BUCKET=... S3_KEY=... S3_SECRET=... BACKUP_PASSPHRASE=... \
    docker compose exec -T web php bin/restore.php --latest --show-key
  # 3. восстановить БД:
  S3_ENDPOINT=... ... BACKUP_PASSPHRASE=... \
    docker compose exec -T web php bin/restore.php --latest --restore-db --yes
  # 4. рестарт панели → она снова видит серверы, клиенты работают.
  ```

## Крон-задачи (в образе)
`check_expired_clients`, `check_traffic_limits`, `monitor_metrics` (watchdog демона метрик/failover), `backup_cron`,
`update_audit_cron` (ежедневный read-only аудит пакетов/awg2/WARP + алерт `server_updates_pending`; ничего не применяет).

## Обновление серверов
Раздел **Обновления** в меню — состояние по всему парку; действия — на карточке сервера.

Правила, зашитые в механизм:
- **Активный член пула защищён** — любое действие требует явного подтверждения.
- **Docker удерживается** при обновлении пакетов ОС: его апгрейд перезапускает демон и рвёт туннели, это отдельная кнопка.
- **Ядро** — отдельное действие (`full-upgrade`), т.к. обычный `upgrade` не ставит новые зависимости.
- **Phased updates** Ubuntu показываются отдельно и не считаются «к обновлению» — они придут сами.
- После каждого действия прогоняются health-checks; если VPN не вернулся, сервер **снимается с авто-failover**.
- **Rolling-обновление пула**: сначала резервные → переключение на проверенный → бывший активный.
  Полностью бесшовным не будет: клиенты держатся за уже отрезолвленный IP и переподключатся при перезагрузке бывшего активного.
